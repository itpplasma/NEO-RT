# Generated direct full-FOW kernels

These files are generated by
`tools/gc_symbolics/app/gen_full_fow_physics.f90` with the pinned fortsym
revision `58a0e06c95ecc943dfdcb044b7ca6a9964c1c55d`.

The generated Fortran modules are runtime-only kernels: they have no CAS
dependency. They must be regenerated into this directory and committed as one
set. Do not hand-edit generated output.

The generator emits cohesive families for action normalization, perturbation,
resonance/base and full contribution weights, Eq.17 force and outer factor,
cylindrical Littlejohn dynamics, axisymmetric P_phi, normalization and paired
quadrature maps, geometry, C/Cdot crossing factors, section reversal, the
sign/symmetry ledger, polynomial cell enclosures, Buchholz limits, refinement
scales, physical/Buchholz invariant conversions, cylindrical Hamiltonian and
launch reconstruction, complex bilinear
interpolation, profile endpoints, profile-potential segments, and the
certificate registry.

Integration hooks:

- `tools/gc_symbolics/fpm.toml` contains the explicit generator executable;
- the main CMake source list contains generated modules in dependency order;
- `check_neort_full_fow_generated` runs
  `tools/gc_symbolics/check_full_fow_generated.cmake` and compares every file;
- `check_neort_gc_class_coordinate_map_generated` regenerates and compares the
  bounded POTATO class-coordinate kernel and its freshness inventory;
- set `NEORT_TEST_TMPDIR` for the regeneration comparison directory (remote
  jobs use `/var/tmp/ert`; the fallback is a checkout-side directory);
- runtime consumers still own domain/status/orbit-topology orchestration.

The certificate registry records stable family IDs, output arities, the pinned
Fortsym revision, and the regeneration command.  Its local identities do not
claim global root multiplicity: interval/theorem orchestration must certify
simple roots and exactly-two crossings.
